Center — AI 코딩 에이전트 지휘 보드

2026.08 ~ 진행 중 · 개인 프로젝트 · 1인 개발 업무에 매일 사용 중

Claude Code · Codex 세션 10여 개를 한 화면에서 굴리는 지휘 보드. 사람이 판단할 일만 사람에게 올라오고, 나머지는 세션끼리 묻고 맡깁니다.

지시 444 건 대화창에서 보낸 지시 · 대장 경유 186
세션 간 협업 62 건 검토 · 위임 요청
승인 카드 98 건 사람이 직접 누른 승인 75
관리 중 세션 15 개 2026.10.21 기준

숫자는 지휘 보드를 연 2026.09.30부터 10.21까지 3주.

흐름
08.26 런처 → 08.27 웹 터미널 타일 뷰 → 09.30 지휘 보드 → 10.02 승인 카드 → 10.16 자동 절전 → 진행 중
형태
Windows · WSL 로컬 웹앱, tmux로 세션 유지, 보드와 대화창 두 화면
규모
백엔드 Python 약 7,600줄(표준 라이브러리) · 화면 약 3,600줄 · API 약 75개 (10.21)
역할
1인 개발 — 설계 · 구현 · Windows 설치기
핵심

세션이 열 개를 넘으면 사람이 병목 — 그래서 정한 다섯 가지

  1. 01
    사람이 할 일만 위로 올린다 터미널 화면에서 권한 · 선택 질문을 감지해 처리함과 데스크톱 알림으로. 창을 돌며 누가 기다리는지 찾지 않는다.
    처리함 · 알림
  2. 02
    승인은 사람이 누른 클릭만 삭제 · 배포 · 재시작은 승인 카드로. 스크립트 · 자동화 응답은 ‘시험 응답’으로 따로 기록해, 에이전트가 스스로 승인한 것처럼 꾸밀 수 없다.
    98건 중 사람 75
  3. 03
    세션끼리 묻고 맡기되, 서로 기다리다 멈추지 않게 의견만 구하는 검토와 일을 맡기는 위임을 나눈 협업 API. 상대당 동시 1건, 상대가 내 답을 기다리는 중이면 새 요청은 바로 거절, 시간 제한.
    협업 62건
  4. 04
    위험한 입력은 보내기 전에 막는다 로그인 · 권한 우회 명령과 한 글자 키는 전송 불가, 다른 세션의 권한 질문에 대신 답하기 금지. 자원마다 주인을 정해, 주인 아닌 세션에 일을 맡기면 경고.
    주인 표
  5. 05
    메모리가 빠듯해도 세션을 여러 개 오래 쉰 세션은 대화를 남긴 채 절전, 말을 걸면 깨워서 전달. 작업 중이거나 예약이 걸린 세션은 끄지 않는다. 재부팅해도 이어서 복구.
    관리 중 15개
실사용

터진 것 → 막은 것

  1. 10.02
    두 세션이 서로의 답을 기다리다 둘 다 시간 초과 → 상대가 내 답을 기다리는 중이면 새 요청을 즉시 돌려보내고, 알림만 필요한 요청은 답을 기다리지 않게.
  2. 10.16
    절전시킨 세션의 표시가 사라짐 → 끄는 몇 초 사이 화면들이 상태를 읽어 ‘살아 있음’으로 판단한 것. 끄는 동안 그 세션 기록을 잠그고, 끈 뒤 다시 확인.
  3. 10.19
    대화창이 깜빡이고 스크롤이 위아래로 튐 → 측정으로 원인(다시 그릴 때 화면 밖 높이를 잊는 브라우저 최적화 설정)을 찾아 CSS 한 줄을 빼서 해결.
